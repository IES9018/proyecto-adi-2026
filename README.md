## 🎯 Propósito del Repositorio
Este espacio contiene el entorno base para el desarrollo de los Trabajos Prácticos de ADI. Aquí aplicaremos el enfoque **Spec-Driven Development (SDD)**, la Metáfora del Arquitecto, el diseño de interfaces (Web/Mobile) y la configuración de arneses de IA para evitar la deuda técnica del *Vibe Coding*.

## 📌 Reglas de Gobernanza y Formato
1. **Política de Repositorios Individuales:** Queda **estrictamente prohibido el uso de Forks personales**. Todo proyecto de alumno debe crearse como un repositorio propio dentro de la organización de GitHub `IES9018` bajo la nomenclatura: `<nombre_alumno>-<nombre_proyecto>` (ej. `analia-crm`).
2. **Estructura Obligatoria:** Todo trabajo debe contar con su especificación formal (`SPEC.md`), su registro de decisiones (`docs/adr/`) y su arnés de control (`.opencoderules` + `INSTRUCTIONS.md`).
3. **Rol Docente:** El docente actúa como *Capataz/Arquitecto de Obra*, realizando auditorías deterministas mediante CLI sobre tus entregas.
